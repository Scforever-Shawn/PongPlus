# P2P / IP 直连联机

PongPlus 的联机模式使用 Godot 4 `ENetMultiplayerPeer`，采用主机权威（host-authoritative）模型。

## 当前协议

- 传输：ENet / UDP
- 默认端口：`7777`
- 最大远端玩家数：1
- 主机：P1，负责球、碰撞、比分、道具和 P2 物理移动
- 客户端：P2，只发送移动/Parry 输入并接收主机状态快照
- 状态快照：约 30 Hz，不可靠有序传输
- Parry：可靠 RPC，避免关键按键事件因为丢包消失

## 使用方法

启动游戏后会出现模式菜单：

1. **本地对战（P2 为 AI）**：保持原来的单机模式。
2. **创建主机**：监听 UDP `7777`，等待一个客户端连接。
3. **连接主机**：输入主机 IP 后连接。

主机和客户端在联机模式都使用：

- `W`：上移
- `S`：下移
- `Space`：Parry

### 同一局域网

客户端填写主机的局域网 IPv4 地址，例如 `192.168.1.10`。

### 同一台电脑测试

打开两个游戏实例：

- 实例 A：创建主机
- 实例 B：连接 `127.0.0.1`

### 公网直连

主机侧需要满足：

1. Windows/macOS/Linux 防火墙允许 PongPlus 使用 UDP `7777`。
2. 路由器将公网 UDP `7777` 转发到主机电脑的局域网 IP。
3. 客户端填写主机的公网 IPv4 地址。

如果主机宽带位于运营商 CGNAT 后面，没有独立公网 IPv4，则普通端口转发无法完成真正的 IP 直连。这种网络环境需要后续增加 NAT 穿透（STUN/打洞）或中继服务器（TURN/自建 relay）。

## 架构说明

联机模式不采用双方各自模拟球的 lockstep 方案。主机是唯一游戏状态权威：

- P1 输入直接在主机执行。
- P2 客户端持续向 peer `1`（主机）发送方向输入。
- P2 的 Parry 使用单独的可靠 RPC。
- 主机计算碰撞、得分、球速、强化状态和道具生命周期。
- 主机约每秒 30 次向客户端发送球、挡板、Parry、破挡和比分状态。
- 客户端对球和挡板位置做简单插值，降低 30 Hz 快照产生的视觉跳动。

这种实现优先保证两端结果一致，后续可以继续加入客户端预测、延迟补偿和抖动缓冲。

## 建议测试

至少完成以下检查：

- 本地模式仍可正常运行，P2 AI 正常。
- `127.0.0.1` 双实例连接成功。
- 局域网两台电脑通过内网 IP 连接成功。
- 双方移动与 Parry 均可操作。
- 球碰撞、得分、回合重置两端一致。
- 道具位置、拾取、强化和过期两端一致。
- 客户端退出后，主机回到等待连接状态。
- 主机退出后，客户端显示断开状态。
- 公网环境放行/转发 UDP `7777` 后可建立连接。
